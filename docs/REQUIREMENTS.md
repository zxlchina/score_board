# 儿童积分计分板 — 产品需求说明

## 1. 项目定位

| 项 | 说明 |
|----|------|
| 目标 | 为家长/老师提供「积分奖励与扣除」工具，便于给小朋友做正向激励与规则约束 |
| 使用场景 | 家庭日常、小组活动等小规模使用 |
| 核心原则 | **游客只读**；**管理员**维护数据并录入积分 |

原始诉求见仓库根目录 [Readme](../Readme)。

---

## 2. 角色与权限

| 角色 | 能力 |
|------|------|
| **游客（未登录）** | 查看小朋友列表、每人当前总积分、积分明细（含原因分类与备注） |
| **管理员（已登录）** | 管理小朋友、录入奖励/扣除、维护原因分类、查看全部数据（含停用对象，若启用该能力） |

**权限规则**

- 所有写操作（增删改）必须经过管理员身份校验。
- 游客无需账号即可浏览公开数据。

---

## 3. 核心概念

1. **小朋友**：计分对象，可多个；至少包含展示名称。
2. **积分变动（记录）**：小朋友 + 分值（正为奖励、负为扣除）+ 原因分类 + 备注 + 操作时间。
3. **原因分类**：与「奖励」或「扣除」类型对应；录入时必须选择分类。
4. **总积分**：该小朋友所有有效变动分值之和；明细按时间倒序展示。

---

## 4. 功能需求

### 4.1 游客端

**小朋友列表（首页）**

- 展示所有「启用中」的小朋友。
- 每项显示：姓名、当前总积分（醒目）。
- 可选（MVP 可简化）：最近一次变动摘要。

**小朋友详情**

- 显示总积分。
- 明细列表字段：时间、类型（奖励/扣除）、分值、原因分类、备注。
- 筛选：全部 / 仅奖励 / 仅扣除（MVP 建议包含）。
- 记录较多时分页或「加载更多」。

**明确不做（MVP）**

- 登录、编辑、导出。

### 4.2 管理端

**登录 / 登出**

- 管理员认证后会话保持；过期或登出后写操作不可用。

**小朋友管理**

- 新增：姓名必填。
- 编辑：修改姓名、排序等。
- **停用**（推荐）：游客列表不展示，历史积分与明细保留；优于物理删除。
- 排序：影响游客端展示顺序（拖拽或序号）。

**积分录入**

- 选择小朋友（MVP：单选；批量同规则录入为二期）。
- 选择类型：**奖励** 或 **扣除**。
- 选择 **原因分类**（须与类型一致）。
- 填写 **分值**（录入为正数，系统按类型存为正/负分，规则全项目统一）。
- 填写 **备注**（可选，建议上限 200 字）。
- 提交后总积分与明细对游客即时可见。

**原因分类管理**

- 增删改分类名称；标记为奖励类或扣除类。
- 已被历史记录引用的分类：禁止硬删，或改为「禁用、不可再选」。

**管理端查看**

- 与游客相同的总览与明细。
- 可查看停用小朋友及其历史（若采用停用策略）。

### 4.3 业务规则

- **总积分**：`sum(有效变动分值)`；停用小朋友是否仍在管理端显示历史总积分——**是**。
- **审计**：每条记录保存 `created_at`；有多管理员时再增加 `created_by`。
- **历史修正（MVP）**：仅支持**追加**新记录；纠错通过再记一条反向分 + 备注说明；单条编辑/作废为二期。

## 5. 信息架构（页面）

```
/                      游客：小朋友列表 + 总积分
/children/:id          游客：某小朋友明细
/admin/login           管理员登录
/admin                 管理首页（快捷录入入口）
/admin/children        小朋友管理
/admin/records         积分录入 / 最近记录
/admin/categories      原因分类管理
```

实现时可合并页面，但能力须覆盖上表。

---

## 6. 数据模型（草案）

```
Child
  id, name, sort_order, is_active, created_at
  （二期可选：avatar_url, note）

Category
  id, name, type(reward | deduct), sort_order, is_active

ScoreRecord
  id, child_id, category_id, points(signed int), note?, created_at
  （二期可选：created_by）

AdminAuth
  MVP：环境变量或配置文件中的单一管理员口令/密钥，不强制独立 AdminUser 表
```

**约束**

- 奖励类记录 `points > 0`，扣除类 `points < 0`（或存绝对值 + type 字段，择一并在全项目统一）。
- 所选 `category.type` 必须与录入时的奖励/扣除一致。

---

## 7. 非功能需求

- **架构**：**必须有独立服务端进程**（Node 等），负责 API、鉴权、数据库与业务规则；不得采用纯静态托管且无后端写保护的方案。
- **部署**：**lichzhang.net** `/tools/score_board/`（`/tools/` 预留其它工具）；线上 `/data1/release/tools/score_board/`；本地 **`MyProject/score_board/`**；见 [部署.md](../部署.md)。
- **终端**：优先移动端浏览器；兼顾桌面（含孩子查看场景）。
- **规模**：小朋友数量、记录在百～千级；列表需分页或懒加载。
- **安全**：管理 API 仅在服务端鉴权；HttpOnly Session Cookie；生产 HTTPS；口令与密钥仅环境变量。
- **持久化**：SQLite 文件（或同等单机库）位于服务器**持久化卷**，容器重建不丢数据。
- **备份**：定期备份数据库文件（含部署文档中的目录说明）。

## 8. 产品决策（默认方案）

以下在未单独确认前，作为 **MVP 默认**；变更时更新本节。

| 议题 | 默认方案 |
|------|----------|
| 管理员账号 | 单一共享口令（环境变量配置）；二期可扩展用户名+密码、多人 |
| 备注 | **分类必选**；备注可选 |
| 原因分类 | 内置若干默认项 + 支持自定义增删改（禁用优于硬删） |
| 批量录入 | 第一版不做 |
| 历史修改 | 仅追加；冲正用反向记录 |
| 语言与展示 | 简体中文；**不做公开排行榜**，仅按人展示总积分与明细 |
| 技术栈 / 部署 | Node 服务端 + SQLite；自建部署 **lichzhang.net**，见 [TECH.md](./TECH.md)、[DEPLOY.md](./DEPLOY.md) |

## 9. MVP 与二期

### MVP（第一版交付）

- [ ] 游客：列表 + 详情明细 + 奖励/扣除筛选
- [ ] 管理员：登录、小朋友增/list/停用、单条奖励/扣除录入
- [ ] 原因分类：内置默认 + 基本维护
- [ ] 总积分自动汇总
- [ ] 未登录访问写接口返回 401/403

### 二期（可选）

- 分类完整 CRUD 策略细化、时间范围筛选、批量录入、记录作废/编辑、导出、多管理员、头像、大屏展示模式

---

## 10. 验收标准

1. 游客打开首页可见所有启用中小朋友及正确总积分。
2. 游客打开某小朋友详情可见完整明细，筛选奖励/扣除结果正确。
3. 管理员登录后可新增小朋友；停用后游客列表不再展示该小朋友。
4. 管理员录入「奖励 +10、分类 A、备注 B」后，该小朋友总积分 +10，游客明细中可见该条。
5. 管理员录入扣除后总积分减少，分值与类型展示正确。
6. 未携带有效管理员会话时，任意写接口拒绝访问。
